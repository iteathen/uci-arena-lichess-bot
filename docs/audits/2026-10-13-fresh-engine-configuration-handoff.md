# Preserve the selected engine product through Bot composition

The Installer-owned dependency configuration handoff is now merged in Installer PR #220. Bot previously consumed only its engine's inventoried immutable factory profile. Its fresh public generated profile included the real service-managed Book binding and exact timing policy, but those inputs disappeared at consumer composition. Standard one-slot defaults also overwrote an existing validated one-bot policy after preservation, preventing automatic play after an otherwise valid update.

This concerns L-O1/L-O2, L-P2/L-P5, L-A1/L-A5, suite G-O1/G-O2 and C08/C09/C10/C11. Reliable uncontrolled play requires preserving engine-owned semantics and operator-selected provider policy. Component ownership, credential isolation, exact runtime identity and pinned timing authority constrain every candidate. Conditional priority favors a usable composition only inside these hard gates; external wins do not prove causal strength.

Candidates: duplicate Book binding production in Bot (rejected: engine authority); copy a stored engine file (rejected: stale transaction input); continue manual operator option patches (temporary operational recovery only); consume fresh producer configuration through the generic declared dependency and retain immutable runtime/policy authority (selected). Standard defaults before validated editable policy preservation repair the separate owner-assignment defect. Moving preservation after all legacy qualification restrictions was rejected because it could re-enable a disabled extended scheduler.

The Bot publishes an optional configuration dependency for the managed Vector default. Its renderer requires the same admitted portable immutable launch profile and exact component/runtime identity, conservative enabled state and null expected runtime. It forwards bounded scalar options from the fresh producer object. The immutable RequireTimingPolicy/file/digest presence and values must remain exact. Bot neither reads generated Book binding contents nor creates its own source/snapshot authority. Explicit saved external UCI override and factory-profile compatibility remain available. A malformed present fresh object fails composition.

Fifteen new focused regressions all failed before implementation: selected opaque option handoff, twelve identity/policy/scalar rejection cases, missing immutable authority, and one-bot preservation. They now pass with all 46 installer renderer tests. These tests are internal qualification, not deployed product acceptance. Full provider validation, nonauthor review, hosted CI, signed 1.0.48 candidate verification and a guarded public installed replacement remain required. Existing credentials are unchanged.

The first full post-version suite passed 843 tests and explicitly skipped eleven, but failed its provider identity assertion because the test hard-coded 1.0.47. Its expected version now comes from the independently declared package identity while the manifest digest remains exact. No runtime identity check was weakened; the failing log is retained, and the corrected full suite must pass before integration.

Nonauthor review found that preserving a valid legacy multi-slot policy after standard defaults could remove capacity evidence while publishing two slots. A new regression reproduced the omission. Standard composition now requires preserved total slots and startup parallelism exactly one, rejecting incompatible migration before publication while retaining compatible one-bot/one-human settings. Silent capacity reassignment was rejected because it changes owner policy. Both managed-default and explicit-external standard substitutions are covered; prior full-suite results do not qualify this repaired revision.

The repaired revision passed all 47 renderer tests and the final full provider suite: 845 passed, eleven explicit gated skips, zero failures. Contract, vendor, GitHub automation, repository-boundary and diff checks passed. The unchanged signed installed process-identity helper was used as local test instrumentation; this result does not qualify a newly built native launcher or replace the required protected release build. Nonauthor review, exact-head hosted checks and installed acceptance remain distinct gates.
