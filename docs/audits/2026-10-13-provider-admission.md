# Provider admission and remote reconciliation repair

The installed-product timing update exposed two provider defects. Pausing the scheduler stopped outbound creation but did not prevent inbound acceptance. A successful ongoing-game HTTP response with missing `nowPlaying` was treated as an empty list, incorrectly allowing reconciliation to clear pending readiness.

The cause affects local objectives L-O1/L-O2 and remote authority premise L-P1: an operator admission pause and an unknown remote state cannot safely become permission to create games or declare recovery complete. Targets L-T1/L-T5 constrain operational continuity; L-A11 bounds the resulting tests to orchestration logic, not live availability or strength. Existing remote games must continue recovering while admission is paused. These correctness constraints dominate convenience only in the admission/reconciliation conflict; they do not grant authority to abort a game or reset durable work.

Alternatives considered: disabling every event/recovery route would strand existing games; checking pause only at challenge arrival would miss a queued accept whose dispatch occurs after pause; treating unknown HTTP bodies as empty would discard remote authority; adding an extra maintenance-only remote request would not correct normal-run behavior and would require unrelated scopes. The selected repair checks pause before engine preparation and again at serialized accept dispatch, retaining generation-owned cleanup. Normal reconciliation validates the complete response and all unique game identities before any game starts or readiness clears. The existing work-finally boundary remains authoritative.

TDD: ten new regressions failed before implementation, and all twelve new cases pass afterward. Cases cover immediate/queued pause, prepared-child cleanup, malformed/contradictory playing responses, valid empty reconciliation, and existing-game recovery while paused. Updated fake API fixtures emit the required `nbMyTurn` alongside `nowPlaying`.

Contract, automation, vendor-lock, repository-boundary and whitespace checks passed. Tests used the unchanged signed installed native identity helper as an instrument; this does not claim a new native build or candidate qualification.
